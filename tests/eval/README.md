# 真实任务评测集

这组文件评估的是**模型拿到真实任务后怎么路由、怎么改、怎么续**，不是 Markdown 链接是否可达。链接可达由 `tests/test_link_reachability.py` 保证；本目录不重复那一层。

现有单元测试与 `selftest.py` 验证脚本行为；本目录补的是语义行为：

| 文件 | 评什么 | 规模 |
|---|---|---|
| `routing_cases.json` | 真实任务的首读与最终落点 | 26 条 |
| `revision_cases.json` | 改稿是否保真、去套话、不换声音 | 7 组 |
| `drift_cases.json` | 长篇续写是否守住既有状态与叙述声音 | 3 条 |
| `fidelity_cases.json` | 单点语义边界是否被改坏 | 20 条 |
| `validate_eval.py` | 用例结构、文档存在、链接深度与语义族覆盖 | 机器校验 |

## 一、跑之前

评测用例本身**不包含模型输出**。需要另起模型会话，按下面的协议跑，再把结果记回表格。

- 每次只跑一个任务，不把全部用例贴进同一个会话。
- 给模型的入口只有 `SKILL.md` 与 `references/routing.md`；其余文档由模型按路由自行决定是否加载。
- 不提前告诉模型“这是评测”、期望文档或评分维度。
- 记录三件事：首读文档、最终加载文档清单、实际加载篇数。
- 同一模型、同一参数、同一提示模板跑完一轮；模型升级或规则大改后要换新一轮，不拿旧结果续算。

## 二、路由评测

### 记录格式

```json
{
  "run": "2026-11-12 / 模型名 / 参数",
  "runs": [
    {
      "id": "R01",
      "first": "references/editing-workflow.md",
      "final": ["references/editing-workflow.md"],
      "loaded": ["references/editing-workflow.md"]
    }
  ]
}
```

`runs` 必须覆盖全部 26 条。`first` 是模型读完入口后实际打开的第一篇知识文档；`final` 是它最终用来回答的文档；`loaded` 是整轮打开过的知识文档。

### 汇总

```text
python -B tests/eval/validate_eval.py --routing-predictions tests/eval/predictions.example.json
```

输出：

- **首读命中**：`first` 等于 `expect_first`，或在 `accept_first` 里。
- **最终命中**：`final` 与 `expect_final` 至少有一篇相同。
- **平均加载**：每轮实际加载篇数，用来观察是否又把整包读进来。
- **误加载**：命中 `avoid` 的文档；出现即说明路由把任务派错了方向。

这四项分开报，不合成一个总分。首读对、最终错说明分册索引没接上；最终对、首读绕远说明入口提示不够；误加载比低命中更需要先修。

### 结果怎么读

- 26 条是小样本，只能定位明显断点，不能估计泛化准确率。
- 反复用同一批用例调路由提示，会把提示调成对这 26 条过拟合；改完提示后应新增未暴露的任务再测。
- 模型自评、同一会话内的“我刚才选对了吗”不算独立评测。

## 三、改稿盲评

### 生成两版

每组用例生成两版改稿：

- **A 版**：允许使用本技能（编辑流程、文体专章、必要时的静态扫描）。
- **B 版**：同一模型、同一参数，不给本技能，只给同样的用户要求和原文。

生成后由第三人把 A/B 随机换名，评阅者只看到“版本一/版本二”，不知道哪版用了技能。两组都不得看到评分维度之外的期望答案。

### 评分

每位评阅者对每版按 1–5 分打五项：

1. 事实保真：`preserve` 是否全部保住，有没有新增无法核实的内容。
2. 信息密度：套话是否减少，必要信息是否还在。
3. 句式自然：长短句、语序、连接是否像人说话。
4. 套话清除：总结式路标、空泛展望、抽象名词化、礼貌框架是否减少。
5. 声音与场合：是否符合目标文体、责任边界与说话人身份。

再记一个二选一偏好：版本一、版本二或持平。评阅者至少两人；意见分歧不强行平均，记下分歧点。

评分表模板：`score_sheet_revision.csv`。

### 结果怎么读

- 只看“偏好”比例不够，要看五项里哪一项在拉动偏好；事实保真掉分的版本不能因为“更像人”判赢。
- 7 组不是 7 个独立文体样本，不能外推为“本技能改稿平均提升多少”。
- 评阅者若看过改稿规则、或由生成模型自评，不能称为盲评。

## 四、长篇续写漂移

每条用例只给：前提、既有状态、前三章大纲、已写正文、续写任务。**不把 `checkpoints` 和 `traps` 给生成模型**，它们只给评阅者。

生成后按五项记录：

- 连续性违规：`checkpoints` 被破坏的条数，逐条标位置。
- 大纲贴合：0–3 分，见 `drift_cases.json` 的 `scoring`。
- 声音漂移：0–3 分，是否从场景叙述滑成概述、总结或另一种文体。
- 复述注水：0–3 分，是否用前情回顾或梗概替代续写。
- 新增事实：列出无法由前提、状态或正文推出的设定、数字、人物关系。

评分表模板：`score_sheet_drift.csv`。

3 条覆盖都市悬疑、古代权谋、近未来科幻，只用于暴露“写着写着忘了设定”的明显问题，不构成对长篇能力的整体评估。

## 五、语义保真探针

20 条短探针，覆盖 10 个语义族：缺数据、推测归因、独立列举、进行/计划、范围否定、未知施事者、作者样本、引语、条件与前后顺序、授权边界。它不评整体改稿质量，只看单点语义边界有没有被改坏；与第三节的改稿盲评互补。

### 跑法

- 每条只给生成模型 `request` 与 `input`；`preserve`、`traps`、`must_not_add`、`why` 只给评阅者。
- A 版允许使用本技能；B 版同一模型、同一参数，不给技能，只给同样的要求与原文。生成后 A/B 随机换名。
- 每条独立会话，不把 20 条贴进同一个上下文，也不提前说“这是评测”。
- 评阅者至少两人，按六维打 1–5 分：事实保真、无新增事实、限定/否定/范围、归因与引语、列举与条件完整性、文体与声音。
- 记二选一偏好与分歧点；事实保真掉分的版本不能因为“更像人”判赢。
- 不提供参考答案。不要把这 20 条改写成“标准改写”再让模型对齐，否则评的就是模仿，不是保真。

评分表模板：`fidelity_sheet.csv`。

### 结果怎么读

- 20 条是探针，不是代表性样本，不能外推“本技能平均提升多少”。
- 反复用同一批用例调提示会过拟合；改完提示或规则后应新增未暴露用例。
- 机器只校验结构（条数、语义族覆盖、字段、无参考答案），不判断语义是否真的保住。

## 六、维护

新增或拆分知识文档时，同步检查 `routing_cases.json`：

- 症状对应文档改名，`expect_first` / `expect_final` / `accept_first` / `avoid` 一起改。
- 新分册若成为某类任务的标准落点，补一条真实任务用例。
- 运行 `python -B tests/eval/validate_eval.py`，再做全量 `unittest`。

校验脚本检查：用例数量、id 与任务不重复、目标文档存在、从 `SKILL.md` 不超过 3 跳、从 `routing.md` 不超过 2 跳、改稿与漂移用例的最低字段数，以及语义保真用例的条数、语义族覆盖和“不提供参考答案”。它不判断用例写得像不像真实任务，也不判断模型选得对不对。
