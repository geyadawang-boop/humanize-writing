# 小说：从立项到整部修订

适用长篇、网文和跨会话中篇。短篇按所选形式明确范围、写正文并回读，不为一篇短作初始化整套台账，也不强制套行动与转折序列。执行工具和状态协议见 [project-workflow.md](project-workflow.md)，知识索引见 [routing.md](routing.md)。

## 1. 先定义“写完什么”

用现有需求确定：读者与题材、预期长度或章节范围、叙述人称、基调、允许内容、必须保留设定、最终交付形式。明确“整部完结 / 当前卷 / 连载到某章 / 仅规划 / 样章”之一。没有输入的主方向可简要给合理假设，不重复索取用户已提供的信息。

长篇启动先明确持续关注的人物与处境、读者期待、叙述方式和收束方向。目标驱动的故事再核对欲望、阻力、选择与代价；稳定人物、群像、回忆或循环结构按自身任务计划，不为了立项强造转变。结局方向可修订，但要留下原因和受影响章节，不能只在末章突然改规则解围。

### 定长长篇与长期连载分别执行

篇幅、题材与发布方式分别判断。长篇网文可以先写完整本再发布，文学性小说也可以连载；不能用平台名、字数或“男频/女频”替代具体作品契约。

| 工作方式 | 前期重点 | 写作中重点 | 收尾证据 |
|---|---|---|---|
| 有明确终局的整部长篇 | 核心关系与主题、全书因果、视角结构、关键转折和结局；可分部，不强制分卷升级 | 中段变化、延续或反复是否服务本作；群像与支线有具体作用；前中后声音和时间线一致 | 全部约定正文；结构修订、人物弧线与主题回响；跨章改动已追踪 |
| 滚动发布的长篇网文 | 本书读者承诺、长线方向、当前卷局部结局、近期章纲；依实际条件约定更新安排 | 逐章兑现与新问题相连；换卷带出关系、资源、伤势和因果；反馈先诊断再决定改纲 | 每卷有自身结果；完本时处置整书承诺；暂停、当前卷完结与全书完结分别标记 |

连载反馈是待判断的证据：区分读者不理解、节奏拖延、题材不合与个别偏好，回到正文定位再改。不可因一条评论推翻角色动机；已发布章需要改动时记录受影响章节和版本。平台更新/推荐规则按当次官方稿约核实，不能把旧资料数字当成当前义务。

缺少的是专业事实、具体作品资料或知识案例时，按[资料补充与验证](material-intake.md)定向索取；缺少的是长篇实写证据时，必须实际创作和审读，不能靠多收教程替代。

## 2. 架构分三层，细节滚动展开

| 层 | 现在要有的内容 | 何时更新 |
|---|---|---|
| 全书 | 主线承诺、终局、关键转折、主要人物弧线、篇章边界 | 方向变化、卷末、整书修订 |
| 当前卷/篇章 | 篇章功能、关键关系或阻力、局部收束、与相邻篇章的联系、伏笔埋收 | 开卷及实际剧情偏离时 |
| 接下来几个章节 | POV、起始状态、本章任务、所需行动或叙述、结束状态及下一步 | 每章完成后 |

远期大纲保留必要的因果、时间与叙述联系，不强写几百条会过期的场景指令。转折核对依据和后果，支线说明其人物、处境、主题或结构作用，不要求每条都改变主角选择。篇幅不足时按作品承诺调整计划，不能把约定应展开的关键正文压成几句梗概来伪装完结；作品本就选择的概述另按其效果判断。

## 3. 建立可检索的作品状态

用现有 templates 和项目工具创建外部状态；已有项目先盘点再接入。分清三类信息：

- **已发生事实**：正文确实出现的事件、人物获知信息、时间地点、伤势、物品持有者、关系变化；注明章/场定位。
- **计划**：尚未写出的转折、伏笔预计回收、候选结局。计划不能覆盖已写事实。
- **未决/假设**：还没确定的设定或待查资料，说明会影响什么。

story-bible 是入口与关键承诺；character-sheet 管人物与声音；world-rules 管规则及限制；volume-outline 管篇章；foreshadowing-ledger 管承诺回收；chapter-progress 管实际章节；outline-changelog 管变更；有明确力量体系再用 power-ledger。现实题材没有战力表需求时如实标不适用，而非造一套等级。

机器未覆盖的人物知识、时间/空间、关系、物件和规则须在对应表中人工检查；“台账最近更新”不能证明台账内容正确。

## 4. 每章实际推进

1. 恢复：读状态、当前卷目标、最近正文、当前视角人物事实和本章涉及的伏笔/规则。只靠上轮摘要不足以确认细节时回读原文。
2. 明确单元功能：此章或场在行动、人物、信息、日常经验、情绪、声音或形式上承担什么。需要变化时追踪选择与后果；有意等待、重复或保持原状态时，照实写结束状态，不虚报认知成长或关系转折。
3. 写正文：用适合视角的感知、动作、对白和概述组织，不把台账条目展开成说明书。句子长短服务场景，不填配额。
4. 回读：确认信息投放、人物声音、必要因果、叙述选择、视角边界、节奏和情绪是否成立。直接对白按[对白工艺](dialogue-craft.md)判断，承载时间与信息的叙述按[视角与声音](viewpoint-craft.md)判断，回环按[叙事形式](narratology-craft.md)判断；仅在相关问题出现时选读。章末可悬念、决定、余韵或阶段解决，按作品契约选择。
5. 更新：把**实际**事件写入台账；计划变更记录原因与后续影响；更新当前章/卷、未决事项和接续位置。
6. 检查与保存：执行项目 checkpoint/check，小说台账再跑 ledger_check；人工核对报警依据。正文改动后旧评阅须失效，不能只更新日期消警。

断点交接包含：最后完成单元、未完成段落、角色当下目标、下一场起点、待回收承诺、待处理矛盾、必要文件路径。写到限制时准确报告阶段成果，下一次直接恢复。

## 5. 类型专门核查

| 类型 | 额外核对 | 常见失效 |
|---|---|---|
| 悬疑/推理 | 线索呈现时点、可知信息、真相与误导、推理链 | 凶手/关键规则到结尾才出现；藏信息冒充公平反转 |
| 奇幻/仙侠/武侠 | 能力条件、资源、代价、敌我认知、成长前置 | 临时开能力、无代价越级、配角集体降智 |
| 科幻/历史 | 事实资料与虚构前提分栏，因果后果一贯 | 未核实技术/史实当证据；设定随剧情改变 |
| 言情/人物关系 | 双方欲望、边界、行为选择、关系推进台阶 | 只靠误会拉长，创伤/和解没有过程 |
| 校园/青春 | [题材指南](campus-youth-craft.md)：学段/年龄、校历、关系与知情状态；真实制度按项目核实 | 成年人替学生作完所有决定；换学期忘年龄；强制逆袭、恋爱或和解 |
| 现实/文学 | 社会处境、人物经验、动机与叙述声音 | 空泛标签抹掉人物差异，或议论挤掉作品已承诺的具体内容；有效概述和评论可保留 |
| 无限流/单元冒险 | 单元规则、局部结局、资源带出、主线联系 | 重复未承担本作功能或挤掉已承诺内容，换地图抹掉前卷结果；无新代价不单独判错 |

这些是阅读问题，不是已经被脚本全自动判定的指标。资料不够先标缺口；当前平台规则或专业事实需要时另核来源。

## 6. 卷末与修订

卷末核对本篇章的局部目标或其他叙述任务如何收束，以及与整书的联系。可以推进、延续或有意悬置，不能仅凭主线未改变判失败。抽查前/中/末章人物声口、重要承诺及配角作用，涉及胜负再核原因；长作品不能仅抽样宣称全文无矛盾。

修订顺序：全书因果/结局 → 人物与场景 → 段落和语言 → 格式与错字。设置事实变更影响表；更改某能力、身份、道具或时间后，检索所有受影响章节并重新评阅。计数字段只说明覆盖，不代替逐章读稿。

出现中段停滞、人物漂移、重复剧情或仓促结尾时，按[长篇结构修订](longform-revision.md)从实稿反推章场功能，再选择最小有效修改。该页也提供末段承诺到实际落点的收束计划；不把教程百分比或案例成败判断变成通用硬规则。

## 7. 整书完成的证据

- 约定范围的正文真实存在且逐章登记，字数/章数与计划差异已说明；没有占位、重复凑数或“此处略”。
- 按本作契约完成主要问题、人物经验与收束；承诺解决的冲突须有结果。人物若发生转变，应有前文支撑；稳定人物、有意停滞或首尾整段复现不自动判作未完成。涉及高潮与解决时，核对已建立条件及后果，不因容许回环而放弃承诺检查。
- 重要伏笔/读者承诺逐条有正文回收或可解释的处置。留续作不能用来逃掉本卷核心问题，开放结局也须回应作品自身的承诺。
- 时间、空间、知识、伤势/资源/能力、人物关系和物件状态已与正文核对；不以“每卷更新一次”取代内容核实。
- 最终质量评阅写明位置与依据，区分作者/模型自评、独立读者试读和真实长篇验证。
- 项目完整性检查与台账检查通过只代表记录层验收；文笔、审美与商业表现仍需读者和编辑判断。

不能以“能写一个合格开头”外推“已证明能稳定写完几十万字”。能力报告必须指明已经实际完成的作品规模与验证方式。
