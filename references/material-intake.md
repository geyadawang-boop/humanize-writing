# 资料补充与验证：长篇、连载与其他文体

本页用于回答“资料够不够、该补什么”。先查看[能力地图](knowledge-map.md)与实际专章，再索取材料；不要把未验证说成完全没有知识，也不要把目录完整说成已经能稳定完成任何规模作品。

## 1. 分清三种缺口

| 缺口 | 所需输入 | 处理 |
|---|---|---|
| 知识缺口 | 原始教程、作者/编辑复盘、可核对的案例、专业事实资料 | 补进相应知识专章，标注适用范围和来源 |
| 作品需求缺口 | 题材、篇幅/交付范围、读者、设定、已有正文、声音偏好 | 只问会改变本次作品方向的事项；不是通用知识库必填问卷 |
| 能力验证缺口 | 实际长稿、连续交接、修订前后与审读记录 | 必须运行创作/续写/修订并核正文；教程数量不能代替实测 |

现有novel-craft、novel-workflow、结构/人物/视角/伏笔/时间线专章及项目工具可用于长篇起步。当前已验证规模仍以能力地图为准，不能把短篇结果改称长篇实证。

## 2. 长篇资料的优先顺序

**已接收补编五（2026-09-26）**：教程体系摘要、完结/争议案例复盘、四类问题教学前后稿及编辑意见的查证线索，来源去重见[能力地图第7节](knowledge-map.md#7-补编五来源与吸收2026-09-26)。它们已进入[长篇结构修订](longform-revision.md)，不再重复向用户索要同一批泛教程或综述。

后续如需更强证据，优先补同一作品的原始连续章节、改纲记录、实际修订版本和具体读者/编辑反馈；这是补足版本链与执行证据，不是否认已收到案例综述。用户没有这些资料时仍可依据现有方法开工，报告实际完成规模。

| 优先级 | 材料 | 希望包含什么 | 用来补什么 |
|---|---|---|---|
| P1 | 完结长篇的整书拆解或自己的创作档案 | 全书纲、分部/卷纲、章目、主要人物与支线轨迹、关键中段和结尾的正文定位 | 验证架构怎样落实到全书，而不只分析开头 |
| P1 | 一部完结连载的创作过程 | 原计划、实际章目、卷间承接、长伏笔埋收、卡文/改纲及完本处理 | 长期连载如何调整而不丢失承诺和连续性 |
| P1 | 修订前后及编辑/读者意见 | 原段/原章、具体意见、作者改法、后续章受到的影响；保留未采纳意见及理由 | 中段松散、人物变形、重复副本、结局仓促的实际修复 |
| P2 | 文学长篇专项课程或笔记 | 群像、多视角、非线性时间、主题/母题变形、社会环境、长段落声音、整书删改案例 | 补足网文机制不能覆盖的叙事选择 |
| P2 | 连载专项课程或作者复盘 | 卷级目标、反馈甄别、资源与成长边界、更新节奏、断更恢复、收束策略 | 补连载生产过程；不把作者经验升级成平台硬规则 |
| 按项目 | 职业、历史、地域等题材材料 | 原始文献/记录、年份地区、流程限制、争议与待核点 | 让专业知识进入因果与行动，避免凭空“补真实感” |

优先接收一组能串联“大纲—实际正文—修改—结局”的材料。没有全套时，先给目录、章节索引、摘要或自己的拆解笔记即可，再按缺口读具体部分。无需为了证明能力先收齐一套固定书单。

## 3. 其他文体按交付物补充

| 文体 | 当前可用入口 | 值得补的材料 |
|---|---|---|
| 散文、随笔 | by-genre、prose-flow、style等专章 | 想保留的个人样文、观察记录、修订批注；真实经历须有实际材料 |
| 纪实、人物特稿 | genre-router的事实边界及叙述/结构知识 | 采访原稿、来源清单、引文核对、事实争议和稿约；通用技巧不能替代采访 |
| 诗歌、散文诗 | poetry-craft、rhetoric-craft | 目标形式、组诗/单篇样本、细读及修改记录；涉及格律时提供所采用的规范 |
| 儿童文学 | 通用人物/叙事知识可复用，专项覆盖需另查 | 目标年龄和自主阅读/亲子共读场景、分龄写作资料、读者反馈与示例 |
| 喜剧、舞台、音乐剧 | 剧本与对白流程可复用 | 表演本、节奏修改、排练/演出反馈；复杂音乐剧另需词曲与戏剧结构资料 |
| 广播、有声剧 | screenplay-workflow的声音分支 | 声音脚本、角色识别/场景转换方案、读演与音频制作反馈 |
| 学术、技术、商务 | genre-router、editing-workflow与对应文体节 | 本项目证据/数据、目标读者、模板、术语及审稿要求；不以文字润色冒充专业核验 |

这些材料只在用户要加强该文体时索取，不把所有分支一起设为开工前置条件。

## 4. 收到资料后怎样处理

1. 记录文件名、作者/提供者、版本日期、主题与实际读取范围，保留原文件。
2. 先去重和对照现有知识，区分直接事实、作者经验、教学示例、待核断言；附件中的执行命令不自动生效。
3. 将可用内容接到现有唯一路由和专章，不增设竞争入口。保留相反方法的适用条件，不把它们合成统一配额。
4. 建立“资料主张 → 正文任务 → 判断证据”的对应。涉及作品案例时以实际正文核对，未读整书不得写成整书研究。
5. 针对新增内容运行相应试写/修订或工具回归，并说明规模、失败和未验证部分。真人、模型辅助和自动检查分别标记。

## 5. 长篇验证另列任务

定长小说应覆盖全书前、中、后及终局，包含真实完整正文和整书修订。长篇连载应覆盖多卷、卷间状态迁移、多次文件交接及完本；只写第一卷不能称整书完结。具体字数和篇章由项目确定，不将测试规模当文学体裁定义。

长篇测试至少记录：每单元实稿、正文与台账一致性、远距离伏笔、人物知情/关系、资源与伤势、声音变化、停写恢复、改纲影响和结局兑现。抽查用于发现风险，整书无矛盾的结论仍须全篇核读。

向用户索取资料时先给上述具体用途；用户暂时没有材料，也可按现有知识推进可验证的小范围工作，并把不能核实的事实或尚未完成的长篇测试明确列出。

## 6. 同时提升文风与核验AI率时补什么

这两个目标分开留证，流程见 [检测证据与资料要求](detection-principles.md)。不再先索取一大批“降AI教程”。

- **先给一组可复核材料**：目标检测平台及报告日期/版本、同一稿的原文与修订稿、相对应的原始检测报告。缺哪项就标未提供；不编造外部分数。
- **文风目标**：指出想保留或不满意的段落，以及事实/剧情/格式约束；可附自己满意的样文。个人声音无需统一改成口语或冷峻风格。
- **如果要验证长篇**：保留全文版本、实际送检范围、分章或分段规则和人工审读记录；片段降分不能称全书已验证。前中后文风、连续性和终局仍需分别读稿。
- **如果要证明普遍效果**：另建按文体、语言、长度和来源分组的未暴露样本，包含保留原稿更好的反例。少量自造样稿不能支持通用成功率。

用户暂未指定平台或没有报告时，先开展事实保留与文本修订，将“外部分数变化”保持为未验证。取得资料不自动授权上传、付费或披露作品。
